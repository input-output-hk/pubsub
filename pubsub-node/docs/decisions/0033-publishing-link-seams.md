# 0033 — Publishing-link seams: deterministic trigger, degree/domain separation, role-aware acceptance

**Status**: Accepted (feature 015; builds on ADR 0032). **§1–2 amended by ADR 0034**: the M3 trigger is superseded — the published model (`formal_spec/hybrid_dissemination/models/m3/README.md`) establishes the standing initiation links unconditionally, and the separate `PublishStrategy` seam merged into the role-parameterised `LinkSelectionStrategy` family. §3–5 (independent draw, role-aware acceptance, publisher-binding receive gate) remain in force.

**Context**: the M3 model (logbook 2026-07-09) needs a publisher whose messages have no relay path into the overlay — a node nobody hash-selected as an upstream — to form **publishing links** that carry only its own locally-originated messages. The 015 spec fixes the establishment machinery (same strategy seams as relay links, on the same `Heartbeat` dial tick), the parameterisation (`publish_degree`, independent of `relay_degree`, distinct hash domain), the trigger (no relay downstream on the topic), and the acceptance posture (policy in interchangeable strategies; publish admissions never counted against the relay `OC`). Two points the spec leaves to the plan are resolved here per Constitution IV.

## Decision

1. **A fourth seam.** `PublishStrategy::expected_publish(&NodeView) -> BTreeSet<(PeerId, TopicId)>` beside the three existing seams (ADR 0029 layout: `strategies/publish/`, trait in `mod.rs`, one file per policy). v1 kinds: `none` (default — no publishing links, the behaviour-preserving configuration) and `hash-gated` (`HashGatedPublish { self_id, publish_degree, bucket_override }`). `handle_heartbeat` runs the publish pass after the relay dial diff, creating `(peer, topic, Publisher, Out) = AwaitingAccept` entries and sending `Request { role: Publisher }` — same lifecycle, same no-retry semantics as relay dials.
2. **The trigger evaluates *expected*, not observed, downstream.** "No relay downstream on the topic" (the M3 trigger) is computed at dial time from the view: for each candidate `D` on topic `T`, recompute the public relay predicate in the inbound direction (`is_valid_edge(nonce, T, D, self, B)`); the trigger fires iff no candidate would select this node. Pure and reproducible — no dependence on inbound-request timing within the heartbeat. Under the default seams (`connect-to-all` ⇒ `B = 1`) every candidate is expected downstream, so the trigger never fires — behaviour preservation by construction. **Residual (documented)**: observed downstream can under-fill expected (over-capacity rejections, un-synced peers), leaving a node with zero actual downstream and no publishing links until a later heartbeat/epoch — the same under-fill class 005 accepted for relay degree.
3. **Independent draw.** The publish predicate is the relay predicate under its own domain-separation tag `pubsub/bucketed-pull/publish-edge/v1` (the relay tag's bytes are untouched), with buckets derived from `publish_degree`. Publish and relay edge sets are therefore independent hash draws; sweeping either degree leaves the other seam's selection unchanged (015 SC-004).
4. **Role-aware acceptance dispatch, second slot.** `NodeState` gains a `publish_acceptance_strategy` beside the relay one; `handle_connection_request` dispatches on the request's carried role. The publish slot is instantiated from the **same four baseline kinds** (`accept-from-all` default | `bounded` | `hash-gated` | `hash-gated-bounded`), constructed with publish parameters: the cap is `⌈publish_degree + c·√publish_degree⌉` counted against `In`/`Publisher` links only (disjoint from the relay `OC` by the role-scoped scan, ADR 0032), and the gate verifies the publish-domain predicate. The readiness gate (ADR 0031) applies to publish requests identically.
5. **Publisher binding on the receive gate** *(surfaced design addition — the spec states only the send side)*. `handle_dissemination` admits a payload iff the deliverer holds an `Active` `Relay`/`Out` link (unchanged) **or** a `Publisher`/`In` link **and the message's `publisher_id` is the link peer**. A foreign-publisher payload over a publish link is dropped with the distinct cause `relay_over_publish_link`. Without this dual, an accepted publish link would function as a general relay path, bypassing the relay-degree topology the caps bound.

## Consequences

- A pure publisher (zero relay links on a topic) injects via its publishing links; a node with expected relay downstream forms none, keeping injection reach and relay RF decoupled (the S-link's purpose).
- Publishing links never carry relayed traffic in either direction: the send side is origin-gated in the fan-out seam (`ForwardToAll` includes `Publisher`/`Out` targets only for `Origin::Local`), the receive side by publisher binding.
- Experiment configs can mix per-node publish strategies freely (e.g. publishers `hash-gated`, everyone else `none`); acceptance baselines sweep per role.
- Duplicate delivery over publish + relay paths is already suppressed by the content-hash dedup at the record point (no new mechanism).

## Alternatives rejected

- **Trigger on observed downstream** — reintroduces intra-heartbeat ordering sensitivity (whether inbound requests landed before the dial pass), breaking reproducibility for the deterministic-framework consumer.
- **Unconditional publishing links** — inflates injection reach for well-connected nodes, exactly the RF coupling the M3 S-link exists to avoid; kept expressible as a future strategy variant since the trigger lives inside the seam.
- **A parallel publish-acceptance strategy family** — four near-duplicate structs; instantiating the existing kinds with publish parameters keeps one family and one prelude invariant.
- **Dial-on-publish establishment** — establishment on the publish path would put wire I/O timing inside the dissemination transition and diverge from the clarified same-tick answer.
