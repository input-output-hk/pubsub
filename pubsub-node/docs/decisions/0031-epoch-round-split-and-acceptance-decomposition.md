# 0031 — Epoch/Round split, readiness-gated acceptance, and decomposed acceptance baselines

**Status**: Accepted (amends 0030; renames 0025's acceptance policy)

**Context**: ADR 0030's `Event::Heartbeat { interval }` fused two roles: the connection-management dial trigger and the round counter the verifiable edge predicate hashes. That coupling meant a retry could not re-request without advancing the randomness (a new interval reshuffles the whole edge set), and the predicate's randomness context was partly strategy configuration (`genesis` fields on the strategies) and partly per-node event state (`interval`) — with no agreement mechanism between two nodes' intervals (N-030). Separately, review of PR #73 found a fail-open admission window (an inbound `Request` racing the registry snapshot fold sees a partially-folded candidate view, floors the derived bucket count to 1, and the predicate degenerates to always-true), and the experiments plan (agreed with Ezequiel) calls for **one-dimensional acceptance baselines** — the cap and the hash gate exercised separately before the compound protocol layers.

## Decision

1. **Epoch and Round are distinct vocabulary and distinct events.** `Event::Heartbeat` (the **round** / dial tick) is parameterless: it consults the connection-selection strategy over the *current* epoch nonce and dials the diff. `Event::Epoch { nonce }` (the **epoch**) folds `NodeState.epoch_nonce` — the randomness context the edge predicate hashes — and produces **no effects**: whether to re-dial under the new nonce is the driver's choice, via a following `Heartbeat`. Within one epoch, repeated heartbeats re-dial the *same* expected set — the retry/back-fill primitive the future retry strategy family (N-029) needs, with no new randomness required.
2. **The predicate hashes one nonce.** `is_valid_edge(nonce, topic, requester, candidate, buckets)` replaces the `(genesis, interval)` pair. `--genesis` becomes the node's **initial epoch nonce** (threaded through `Node::new` into state); the strategies lose their `genesis` fields and read the nonce from `NodeView.epoch_nonce`. The nonce is designed to arrive from an **externally observable event** (block hash / epoch boundary) when the beacon layer lands — the same anchoring N-030 identifies as the robust round-agreement direction; v1 never fires `Epoch`, so both ends always verify under the configured genesis.
3. **Inbound `Request`s are gated on `Synced`** (silent drop, cause `not_synced`). This closes the fail-open pre-snapshot window. Honest scope: it does **not** close post-sync fold lag (the indexer pushes `Synced` even for degraded snapshots, and later membership deltas keep the B-agreement assumption in play — a pinned `--bucket-count` remains the by-construction fix), and a request landing in the acceptor's pre-`Synced` window is lost until a later heartbeat re-requests it — in v1's single-readiness-heartbeat world, a permanent-loss mode, acceptable because the integration wiring delivers `Synced` during construction before any cross-node dial. The epoch analogue (a request computed at nonce *N* verified at *N−1* is a silent drop) is deferred with the periodic-heartbeat layer, which should pair epoch advancement with a two-phase advance-then-dial barrier — the split in (1) is what makes that barrier expressible.
4. **The acceptance seam offers all four one-dimensional baselines** (the empirical approach: establish simple baselines before compound layers): `accept-from-all` (membership only), **`bounded`** (cap only — new), **`hash-gated`** (edge predicate only — new), and **`hash-gated-bounded`** (both — `VerifiableBoundedAcceptance` renamed, aligning the acceptance vocabulary with the dial seam's `hash-gated`). Each is a concrete ~15-line policy; the shared `admit_prelude` (membership → idempotent already-downstream re-Accept, one borrow-only downstream scan) runs first in every refusing policy, so the half-open-link repair invariant lives in one place and a future bounding/gating strategy cannot omit it.
5. **Pre-release versioning convention.** The predicate's domain tag stays at `pubsub/bucketed-pull/edge/v1` across design iterations: there are no deployed peers to stay compatible with, so the suffix starts counting when compatibility starts mattering (the tag's doc comment is the version record).

## Consequences

- Dial cadence and randomness are independently drivable: an experiment can sweep heartbeats within an epoch (retry behaviour) or sweep epochs at fixed cadence (rotation behaviour) without conflating the two.
- The strategies are purer (no randomness configuration on the policy objects); the predicate context is node state, folded from events like every other input.
- Mixed acceptance pairs (e.g. `connect-to-all` dial against `hash-gated-bounded` acceptors) are legal experiment configurations; the stranded-pending cost is documented in the 005 quickstart. No build-time pair coherence check — coherence is a cross-node property a single node cannot see.
- Public API breakage (Event shape, ctors, params structs, `Node::new`) — acceptable at 0.1.0/unpublished.

## Alternatives rejected

- **Epoch as a counter** (`Epoch { epoch }`, predicate keeps `(genesis, epoch)`) — keeps the node owning the counter→randomness pairing and needs a second refactor when the real beacon lands; carrying the nonce directly makes the driver/chain the source, which is the point.
- **Carrying the interval/nonce in the `Request`** — verifying against a requester-claimed round lets an adversary grind values offline until the predicate passes for a victim, defeating the spam resistance (N-030); rejected there, unchanged here.
- **A check-combinator acceptance framework** (ordered `AcceptanceCheck` list) — more general than the four fixed combinations warrant; the shared prelude function captures the one invariant that must not drift, without a framework.
- **A build-time acceptance/connection pair-coherence error or warning** — would reject deliberate experiment configurations (decomposed stages, per-node strategy assignment per N-028/N-031) and cannot see the actual hazard, which is cross-node.
