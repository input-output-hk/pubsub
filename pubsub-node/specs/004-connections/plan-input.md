---

Implement per the converged spec in `specs/004-connections/spec.md` (nine clarify rounds, convergence documented in its Clarifications section), building directly on the merged 004 pure-core architecture (ADR 0011: crate-internal `NodeState` + pure `apply` → `Vec<Effect>` with named per-variant handlers; ADR 0012: `Arc<Mutex<NodeState>>`, spawn-in-constructor, drop-abort) and the merged 008 registry integration (ADR 0013/0014: registry-derived `subscriptions`, `candidates: HashMap<TopicId, HashSet<PeerId>>` with self excluded, node-keyed watch producer).

Pure core: `NodeState` gains `upstream: HashMap<(PeerId, TopicId), UpstreamState>` with `UpstreamState { AwaitingAccept, Active }` and `downstream: HashSet<(PeerId, TopicId)>`; `candidates` and the shell-side bootstrap `peers` field are untouched. `apply` remains the sole state writer; every new arm follows the named-handler convention recursively. The receive path prepends the connection check to `handle_signed_message` per the clarified order (connection → subscription → signature, existing checks unmodified); misbehavior severance happens at the signature step and returns the first-ever inhabited effects.

Protocol surface: a third `Message` variant `Message::Connection(...)` sibling to `SignedMessage`/`PlainMessage` (extends ADR 0010's hierarchy): an inner control payload carrying the emitter `PeerId` and topic per variant (`Request`/`Accepted`/`Terminated`) with the signature computed over that payload following 003's `signed_bytes` pattern — so the signature binds emitter + topic + kind, mirroring how `PlainMessage` binds `publisher_id`. `PeerId` is reshaped from a String newtype to wrap `PublicKey` (the `PublisherId(PublicKey)` pattern; mock keys wrap the existing readable strings so config, fixtures, and logs stay human-legible), aligning node identity with the protocol's pubkey-keyed subscription list — a structural decision requiring its own ADR, whose blast radius (config, network registration, the 008 registry and `MembershipEvent`, candidates, test helpers) is wide but mechanical. Control-message verification happens inside `apply` (the verifier's canonical owner is `NodeState`) using the carried emitter's key; all control handling — self-check, membership validation, entry keying, reply addressing — uses the carried emitter, never the routing frame (per FR-011), while the payload-path connection check keys on the frame's delivering peer (FR-016; frame trust is registration-bound per `network.rs`). Membership validation of Requests reads `subscriptions` + `candidates` exactly as clarified in FR-012. `RoutingFrame` and the `Network` trait/`InMemoryNetwork`/`register`/single `network_mailbox_loop` are unchanged.

Construction and shell: `Node::new` grows a node `Signer` (mock crypto — first time nodes sign; the `crypto::mock` factory provides it) with identity/signer coherence enforced at construction: a `self_id` that does not match the signer's identity returns a new typed `NodeError` variant with no background activity spawned (the mechanism — signer exposing its public key vs. a keypair-shaped parameter — is this plan's choice); the N-006 construction-failure integration test extends to this mismatch alongside duplicate registration. The connection-setup delay is a new `Option`-shaped `NodeConfig` field (TOML, parse-at-the-edge), `None` by default — no timer task spawned, no setup event self-generated; when set, the one-shot timer is a shell-owned ephemeral task (sleep → push the setup event; push-to-closed-queue is already a silent no-op). Effects are executed in the existing event loop's post-apply section, which needs a clone of the network send handle moved into the loop task; effect errors are logged only. The misbehavior effect is semantic (`peer`, `topic`, `cause`) and its executor only logs in this feature.

Strategy: an encapsulated connection-selection abstraction injected at construction and consulted synchronously inside `apply` on each setup event, mapping (own topics, candidates) to the expected upstream set, applied by FR-007's diff rule — dial everything expected that is not Active: missing pairs gain an AwaitingAccept entry plus a Request, pending (AwaitingAccept) pairs are re-dialed keeping their entry, Active pairs are untouched, and expected-set membership never removes anything. Every setup event is processed the same way, whether produced by the optional timer's single fire or injected through the public event intake. The v1 implementation is connect-to-all-candidates; the strategy must be pure/sync (unit-testable without the loop) and shaped so later features can instantiate alternatives from config. Its exact trait shape and injection point (a `NodeState` field beside the verifier, or threaded into `apply`) is a decision this plan must make and record.

Shutdown: `pub async fn shutdown(self)` pushes a Shutdown event; `apply` clears both connection structures and returns one Terminated-notice effect per entry regardless of state; the event doubles as the loop's terminal marker (loop breaks after executing those effects), and `shutdown` awaits the event-loop `JoinHandle` (`(&mut self.event_loop).await` — `JoinHandle` is `Unpin`, and `Node`'s `Drop` impl forbids destructuring; the `JoinError` is logged-ignored), then lets `self` drop. The existing `Drop` stays as-is (abort flags only, order immaterial); this lifecycle extension amends ADR 0012's teardown story and needs an ADR.

Tests: connection state-machine coverage lives as synchronous transition tests in `state.rs`, with multi-step scenarios expressed through a declarative connection-script builder per constitution v1.2.0 (sibling to 008's `MembershipScript`, beside the types it builds); integration suites (`two_node_ping`, `topic_filter`, `n_node_graph`, config loading) are reworked — not preserved — with establishment preambles through the real path (registry `set_topics` → converge → push the setup event via the public `Node::events()` handle → `await_connection`-style helpers in `tests/common`), re-asserting post-connection behavior as the regression boundary. The unset-by-default delay keeps every scripted test free of timer races; exactly one integration test configures a real delay to exercise the timer mechanism itself. Test identity construction: a mock-scheme alias-keypair constructor (private = readable alias bytes, public via `derive_public`, so alias identities sign and verify through the unmodified mock pair) keeps `peer("a")`-style helpers working end-to-end; `PeerId`'s `Display` rendering (UTF-8-when-valid vs. the `PublicKey` hex default) is a readability decision this plan makes alongside the reshape.

Documentation obligations: ADR(s) for the control-message shape together with the key-backed `PeerId` identity reshape, the strategy seam, and the shutdown lifecycle; a supersession note for `specs/event-loop-and-registry-contract.md` §1.3 (per-connection producers deferred to a real connection-oriented transport); `IMPLEMENTATION_NOTES.md` updates — N-002 and N-006 marked resolved here, new deferral entries for the stale-AwaitingAccept GC (trigger: dynamic connection transitions), Active-connection heartbeat/liveness (trigger: 009/real transport), handshake identity-binding hardening (trigger: real crypto), and the misbehavior follow-ups package (blacklist, re-selection, topic-based misbehavior). The plan's design artifacts MUST consolidate the connection staleness model: `data-model.md` carries the upstream/downstream state machines as diagrams (Mermaid state diagrams render natively in the repo's markdown) next to text descriptions, covering every transition the spec defines (entry creation by strategy-dial and by Request, AwaitingAccept → Active, removals via Terminated/misbehavior/shutdown, pending re-dial on repeated setup) — plus a staleness catalog enumerating each deliberately-unreconciled flow with its cause, observable footprint, and the deferred healer: stuck AwaitingAccept (absent peer / pre-convergence drop → re-dial whenever setup recurs, GC at dynamic transitions otherwise); one-sided connections after an acceptor's abrupt restart (→ liveness/dynamic transitions); survivor-side stale entries after abrupt drop (→ requester-restart re-dial heals one direction, liveness the other); own-topic drift (subscription shrinks, Active connections for the dropped topic persist on both ends — the subscription filter protects the recipient meanwhile → registry-driven re-scoping at 012); peer-membership drift (expected set shrinks, held pairs untouched → removal at dynamic transitions); and the misbehavior asymmetry (offender keeps its downstream and keeps sending into drops → blacklist package). Each catalog entry cross-references the spec edge case and the IMPLEMENTATION_NOTES deferral it lands in. Identifiers left for this plan to fix under existing conventions: event/effect/variant names, the new snake_case drop causes under the `message_dropped` convention, the config field name. Operator-facing strings carry no FR citations.
