# PubSub - Bi-Weekly Report: 10 July - 23 July 2026

## Executive Summary

This period locked the model family into the node and took the project public-facing. The weekly sessions confirmed **M3 as the implementation base** for M4/M5, resolved the M5 symmetry question (k_in and k_out are independent), and validated the simulation framework across M2–M5 against the analytical findings — with the reference operating point pinned at N = 20 000, μ = 0.2, target degree 24 and Pr[bad graph] ≤ 10⁻⁴. On the node, the **015 publisher-links feature merged on the final day of the period** ([PR #77](https://github.com/input-output-hk/pubsub/pull/77)): M3 and M5 became per-node configurations of one node, with a symmetric-edge approximation of M4 and the exact M4 recorded as the agreed follow-up. Robustness measurement moved from thresholds to collapse *rates*, quantified via condensation-set sizes. In parallel the repository was prepared for public release (license and disclaimer, code-owners cleanup) and the public website gained the midyear presentation, an animated experiments page and a landing-page refresh; a CIP skeleton landed with sections distributed across tickets, the full CIP itself downgraded to an optional goal in favour of mandatory empirical data. The main near-term gate at period close: land the experiments framework and the remaining selection work so the full experiment program can run.

## [Rust PubSub node prototype](https://github.com/input-output-hk/pubsub/issues/36)

The **015 publisher links** feature merged ([PR #77](https://github.com/input-output-hk/pubsub/pull/77), [`015-publisher-links`](../pubsub-node/specs/015-publisher-links/)), realising the M3 and M5 dissemination models as per-node configurations of the existing node, plus a symmetric configuration approximating M4. Concretely: standing **publisher links** established unconditionally on the readiness heartbeat and carrying — under the default fan-out — only the node's own publications (M3's exclusivity as a sender-side rule, with a kind-agnostic receive gate); **symmetric edges** whose reciprocity is constructed by a dedicated handshake rather than assumed ([ADR 0034](../pubsub-node/docs/decisions/0034-connection-vocabulary-and-constructed-symmetric-reciprocity.md)); and a `forward-to-all` fan-out strategy as deliberately the only switch separating M5 from M3. Links are re-keyed as `LinkKey { topic, peer, kind }`, each handshake gets its own signed wire vocabulary, and a node without the new flags remains the unchanged M2 baseline by construction ([ADR 0032](../pubsub-node/docs/decisions/0032-publisher-links-and-model-family.md)). Earlier in the period the static config bootstrap peer list was removed ([PR #98](https://github.com/input-output-hk/pubsub/pull/98)) — peers come from the registry, completing the registration-driven joining story.

Next: the agreed follow-up is a uniform exactly-RF selection kind to realise the exact M4 (the current symmetric configuration yields a binomial degree with no minimum floor), and connecting the strategy seams to the experiments framework so the model family can be measured rather than argued about.

## [Pub/Sub Phase 2 — empirically-driven architecture](https://github.com/input-output-hk/pubsub/issues/46)

The **simulation framework was validated across M2–M5**: Monte Carlo evaluations align with the prior analytical findings, closing the cross-validation loop the phase is built on. Denis pinned the **reference parameters** — network size 20 000, adversarial fraction 20%, target degree 24, targeting Pr[bad graph] ≤ 10⁻⁴ — and experiments are being rerun at 150 rounds with the five identified experiments targeted for execution. Memory optimisations were identified (peer cloning, message caching) but deliberately deferred: the group agreed to complete all experiment simulations before touching engineering optimisations, keeping the instrument stable through data collection.

Robustness work reframed the question from *where is the threshold* to *how fast does security degrade* once μ exceeds the optimised level: a graph counts as collapsed at a 0.5 probability of a bad graph, and — since model failures manifest mostly as isolated nodes rather than large disconnections — the framework measures strongly connected components and **condensation sets** to quantify partial collapse, with the data to be visualised for the CIP. Engineering bounds entered the picture: per-model message-complexity and bandwidth budgets, with per-link traffic measurements identified as a prototype gap. Two design threads opened: Ezequiel's proposal to split designated **publisher nodes from relay nodes** (retaining M3-level security while relaxing relay requirements, with a natural coupling to collateral/incentives), and gossip-style I-Have/I-Want hash exchanges — deferred, as advertising unheld messages is a new attack surface.

Next: run the five identified experiments and commit the raw data; resolve why M3 comes out unexpectedly efficient compared to M5; evaluate the publisher/relay split under analysis.

## [Analysis of existing pubsub protocols](https://github.com/input-output-hk/pubsub/issues/65)

**M3 was confirmed as the implementation base**, judged the best balance of security and efficiency among the five models, with M4 and M5 to be built from it. The open M5 symmetry question was resolved: **M5 is not symmetric** — k_in and k_out are independent variables, with the sweet spot at k_in = 9, k_out = 8 for N = 20k, μ = 0.2, Pr[bad] ≤ 10⁻⁴ (`m5/properties/full_coverage.md`). Context for the model choice: M5 resembles what some IO protocols already run, but M3 delivers roughly 30% better traffic efficiency — it first builds a "bad graph" and then repairs exactly the broken aspect with its s seeds, where M5's conservative construction pays in inefficiency. Both claims are flagged for experimental cross-validation. Terminology and requirements were sharpened along the way: seed peers exist for publishing only, hash-gating of connection requests is a requirement for both M3 and M5, and the node view splits into explicit relaying and publishing sets (the simpler design, after the abstract-link-type alternative was rejected).

Next: cross-validate the ~30% M3-over-M5 advantage and the per-model formulas against the experiment data as it lands; per-model throughput paragraphs in the node-degrees property file (Denis).
